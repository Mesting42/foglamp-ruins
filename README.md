# 雾灯遗迹

一款使用 Vite、TypeScript、Phaser 3 和 Three.js 制作的浏览器俯视角动作解谜冒险。全程离线运行，不加载运行时 CDN。游戏目标是依次取回五枚灯芯，穿越五段遗迹并重新点亮中央灯塔。关卡地形、墙面、石块、石门、出口、潮汐池和交互建筑由单个 Three.js 场景实时绘制，固定正交俯视相机与 Phaser 关卡坐标共用同一套尺寸。主角使用实时 Three.js 低多边形模型；敌人、首领、NPC 和收集物使用 Three.js 模型纹理。

## 开始

需要 Node.js 20 或更新版本，以及 npm。

    npm install
    npm run dev

发布构建与本地预览：

    npm run build
    npm run preview

品牌徽记为原创 SVG，浏览器标签页使用 `public/favicon.svg`；手机主屏幕图标和 Web App Manifest 图标位于 `public/assets/brand/`。修改矢量徽记后，可在 Windows PowerShell 运行 `powershell -ExecutionPolicy Bypass -File scripts/generate-brand-icons.ps1` 重生成 180、192 和 512 像素 PNG。

## 操作

手机采用**横屏优先、竖屏可玩**：横向关卡在横屏下能显示更多前方路线，左右两侧分别放置摇杆和动作按钮。竖屏提供可关闭的方向建议；“横屏”按钮会尝试全屏和方向锁定，浏览器不支持锁定时提示手动旋转。安装版 Web App 的 Manifest 首选横屏。桌面显示独立的冲刺、雾灯、互动操作栏，支持点击、当前键位及冷却反馈；修改绑定后键帽同步更新。手机和平板保留摇杆与圆形动作按钮。控件根据平台和输入能力选择，不再因为电脑窗口变窄或电脑支持触摸就直接使用手机布局；混合输入电脑可随鼠标、键盘和触摸切换。

| 动作 | 桌面 / 手柄 | 手机 / 平板 |
| --- | --- | --- |
| 移动 | WASD 或方向键；手柄左摇杆 | 左侧虚拟摇杆，支持 Pointer Events 拖动 |
| 冲刺 | 空格 | 冲刺按钮 |
| 使用雾灯 | F、鼠标右键或桌面操作栏雾灯按钮 | 雾灯按钮 |
| 互动 | E；鼠标点击目标可走近后互动 | 互动按钮；点击目标后自动走近 |
| 暂停 | Esc | HUD / 触控暂停按钮 |

桌面与触屏控件分离的修改说明与预览截图见 [桌面操作栏说明](./qa/DESKTOP_CONTROLS.md)。

公开源码包含游戏源码、原创素材、依赖锁文件、QA 报告和文字验证记录；开发依赖、构建产物、临时预览日志与本地回归截图不纳入 Git。QA 文档中提到的截图保留于开发工作区，公开仓库提供相应测试结论和测量数据。

雾灯冲击波会震退普通敌人，并能打断首领蓄力。红色警戒圈表示敌人的攻击预警。生命耗尽或矿井追逐失败后，会从最近的检查点继续。

## 旅程

1. **雾灯草原**：八方向移动、雾灯、基础开关和第一枚灯芯。
2. **回声森林**：探索迷雾小径，按“枝、月、潮”的顺序激活符文。
3. **沉没遗迹**：转动两侧潮阀，让浮台靠岸，并在限时石门关闭前通过。
4. **旧矿井**：激活闸柄和支撑杆，在坍塌追逐计时内冲向升降梯。
5. **灯塔核心**：使用雾灯打断守塔者三个阶段的蓄力，完成结局。

每关含入口、探索区、谜题、敌人或危险、检查点、收集物、出口和阶段完成提示。可选碎片、宝箱与支路为重复游玩提供额外探索内容。

第一关提供四步新手引导：移动、冲刺、雾灯冲击波和点亮引路壁灯。提示会根据实际操作自动推进；桌面、手柄与触屏设备会显示相应的操作方式。玩家可以跳过，引导完成状态会保存在本机存档中。

### 探索与灯焰

引路壁灯之后，草原庭院南北的引光台需要靠近释放雾灯点亮；两座都亮起后，光流会开启庭院门。灯塔核心会再次使用这个机制。回声森林的符文线索藏在回声石碑中，先用雾灯照见，再走近阅读。沉没遗迹的河道有实体阻挡，需激活两处潮阀并乘浮台渡河；限时门关闭后可使用东岸回流闸原地重试。矿井先让玩家观察，再由闸柄触发追逐，检查点旁的安全区可暂时喘息，落石会先显示落点。

每关有一段隐藏记忆。照亮、阅读后会收入主菜单与暂停菜单中的「旅途手记」，并解锁一种可切换的灯焰颜色。手记显示碎片、灯芯、游玩时长、雾灯次数、失败和完成次数；数据仅保存于本机。雾灯冷却为 1.1 秒，冲刺冷却为 0.8 秒，按钮外圈与数字显示恢复进度。守塔者的金色预警末段与攻击后的破绽可被雾灯命中。

现有 `foglamp-save-v1` 存档保留版本号与原字段；新增机关状态、记忆和记录字段在读取旧存档时补默认值。旧检查点后方的门会恢复通行，避免重生后卡在已通过的门后。

### 游戏逻辑检查

    npm run check:gameplay

使用轻量 Phaser 替身检查冲刺、敌人和首领状态、帧率下的判定、存档迁移、机关、渡船重试及静态路径可达性。最终 18 项检查通过；生产构建通过。水关、矿井、首领三阶段和结局已在 IAB Chromium 生产预览中实际通关，并复测七种视口。实现见 [玩法改进报告](./qa/GAMEPLAY_UPDATE.md)，本轮修复、操作证据和设备限制见 [完整流程回归报告](./qa/REGRESSION_REPORT.md)。逻辑检查不能代替真实 Arcade 碰撞、真机性能或首次玩家试玩；关卡标注时长仍是设计目标，25～35 分钟的自然首通尚需首次玩家试玩确认。

## 设置与存档

设置包括低 / 中 / 高画质、粒子、屏幕震动、阴影、后处理、像素比、动态缩放、帧率上限、键位重绑、摇杆尺寸 / 透明度、按钮透明度、鼠标灵敏度、手柄、音量、字幕、高对比度、色觉辅助、减少动态效果、字体大小和恢复默认。帧率默认无上限，由浏览器的 requestAnimationFrame 调度。

存档保存在本机 localStorage，记录解锁关卡、当前关卡、检查点、灯芯碎片、收集物、设置、教学状态和版本号。无法解析或版本不匹配时会恢复默认存档，不会阻止启动。

## 响应式测试记录

2026-10-21 已在 IAB Chromium 中运行生产构建，检查桌面、平板、手机横竖屏共十种视口，并操作摇杆、冲刺、雾灯、暂停、设置和方向提示。最终布局测量、截图、修复说明及未覆盖项目见 [响应式测试报告](./qa/RESPONSIVE_REPORT.md) 和 [QA_CHECKLIST.md](./QA_CHECKLIST.md)。这些结果属于 Chromium 视口模拟；Android / Chrome 真机、多指同时触控、刘海安全区和其他浏览器仍需设备复测。

## 技术结构

- src/main.ts：Phaser 配置、服务初始化和入口。
- src/game/scenes/：启动、预载、主菜单、选关、关卡、暂停、失败和结局场景。
- src/game/entities/：玩家、敌人、首领、交互物与降级精灵工厂。
- src/game/systems/：输入、触控、关卡、音效、性能、设置、存档和 Three.js 模型纹理工厂。
- src/game/data/：五关数据与共享类型。
- src/game/ui/ 与 src/styles/：HTML HUD、菜单、设置和响应式样式。
- public/assets/、public/audio/、public/fonts/：本地素材入口；许可和修改记录见 [ASSET_SOURCES.md](./ASSET_SOURCES.md)。

Phaser 采用 Scale.RESIZE。渲染器使用 Phaser.AUTO，有 WebGL 时优先 WebGL，不可用时自动降级 Canvas；Three.js 环境渲染器初始化失败时改用本地 Canvas 2D 场景绘制。每关只创建一个 Three.js 环境渲染器，角色模型另用一个透明画布；其他角色与收集物的三维网格在预载时烘焙为纹理，避免给每个对象创建 WebGL 上下文。边界、石块和地形碰撞盒由共享关卡布局生成，建筑和机关按模型位置生成相应碰撞体。石门使用 72×200 world px 的门洞实体，永久侧墙连接上下边界，开启时只隐藏中央门体并禁用其碰撞体；人物碰撞框随模型视口缩放。场景素材由程序绘制；音效在本地通过 Web Audio API 合成。
