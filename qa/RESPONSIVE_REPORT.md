# 三端适配检查与修复记录

日期：2026-10-21。项目：雾灯遗迹。优先设备方向：Android / Chrome。

## 环境与范围

使用 IAB Chromium 浏览器，运行 `npm run build` 生成的 Vite 生产产物，通过独立本地预览 `http://127.0.0.1:43871/` 检查。测试通过浏览器真实点击、按住与拖动入口操作，以及 DOM 边界测量和截图完成；没有通过修改游戏内部状态代替操作。使用该独立来源的测试存档。当前环境不能提供真实 Android 硬件或独立 Chrome / Edge / Firefox / Safari，下面的尺寸结果为视口模拟。

## 手机方向选择

**横屏优先，竖屏保留完整操作。** 当前关卡主要沿横向推进，横屏能显示更多前方路径、石门和敌人，左摇杆与右侧动作区也更适合双手操作。竖屏保留菜单、设置与关卡操作，并提供可关闭的横屏建议。横屏入口尝试全屏后请求方向锁定；不支持时提示手动旋转。Manifest 首选 landscape，安装后的实际行为仍需 Android 真机确认。

## 修复内容

1. 统一设备判定：粗指针、触摸能力和宽屏手机布局保持一致；915px 宽的手机横屏不会丢失控件。
2. 摇杆旋钮按中心定位，尺寸设置与响应式尺寸共同生效；140% 设置也受可用空间约束。极小横屏将摇杆限制在 112px。
3. 暂停、失焦、隐藏和旋转清除输入；设置覆盖期间触控层隐藏并禁用，继续后重新挂载并回中。手动摇杆输入会清除旧的点击移动目标。
4. 短横屏动作按钮 56px，竖屏 62px；菜单和设置控件至少 48px，复选框整行可点。设置内容保留内部滚动。
5. 压缩小屏横屏教程并调整位置，避免与摇杆、动作区重叠；交互提示出现时让方向建议隐藏，提示文本按视口换行。
6. 竖屏保留生命和灯芯计数；旋转后相机立即对准主角，避免沿旧位置缓动；主菜单背景重建以铺满新视口。

## 实际操作检查

- 主菜单十种视口可访问，无横向溢出；小高度下可滚动。选关在手机横竖屏、平板竖屏可访问。
- 设置在 360×640 可滚动到末尾；复选框点击行约 261×60px；下拉框、范围输入和键位按钮至少 48px。
- 在小屏横屏按住摇杆移动后教程由 1/4 进入 2/4，松手旋钮回中；冲刺推进至 3/4，雾灯推进至 4/4。本轮未把手机互动步骤及完整关卡通关记为通过。
- 暂停时触控层不可见，无残留 active 按键；暂停中从横屏切到竖屏并打开设置，改变摇杆尺寸后返回、继续，控件恢复并保持回中。
- 点击横屏入口进入全屏；当前环境不能锁定方向时显示“请横转手机，也可继续竖屏游玩”。关闭提示后继续游戏。实际 Android 方向锁定未验证。
- 最终构建中切换视口后画面与主角正常，无新增 error / warn 控制台日志。
